Glossary

Key terms and concepts used throughout Bamwerks. From agent architecture to governance frameworks, this glossary defines the vocabulary of our operations.

A

Agent

A specialized AI instance with a defined role and prompt. Each agent in the Bamwerks swarm has specific responsibilities, swarm membership, and accountability structures.

Agent-Blind Credentials

Security pattern where agents use secrets without seeing them. Credentials are resolved by a broker on behalf of the agent, preventing exposure of sensitive values in agent context or logs.

B

BAMHenge

The Bamwerks logo and favicon, inspired by Stonehenge. Represents the foundational structure and timeless principles of the organization.

C

CHARTER

The governing document owned by the Founder that establishes organizational principles, agent responsibilities, and governance rules. All agents must follow the CHARTER, and only the Founder can modify it.

Credential Broker

System that resolves secrets on behalf of agents without exposing the actual credential values. Enables agent-blind credential patterns and enforces access control policies.

F

FORGE

Framework for Orchestrated Reasoning, Governance & Execution. The unified methodology that governs all Bamwerks operations, combining project-level workflow with agent-level discipline.

FORGE Cycle

Agent-level discipline within the FORGE framework: Reason (understand the task) → Act (execute with specialists) → Reflect (review and verify output) → Verify (QA + Security gates). Every task follows this cycle.

FORGE Workflow

Project-level lifecycle within the FORGE framework: Size (assess task complexity) → Inception (requirements and design) → Construction (parallel execution by specialized agents) → Gate (QA and Security review before shipping).

G

Gate

Quality checkpoint where QA (Hawk) and Security (Sentinel) reviews must both pass before work ships. Gates enforce multi-perspective verification and prevent single-point-of-failure approvals.

H

Hawk

QA reviewer agent responsible for quality assurance. Hawk performs functional testing, validates requirements, and ensures outputs meet specifications before they pass the Quality Gate.

O

OpenClaw

Open-source AI agent platform that powers Bamwerks operations. Provides the runtime, tooling, and orchestration capabilities for multi-agent systems.

Orchestrator

Sir, the COO agent that dispatches and coordinates work across the Bamwerks swarm. The Orchestrator breaks down tasks, assigns them to specialists, and synthesizes results — but never implements directly.

Q

Quality Gate

Parallel QA and Security review checkpoint before shipping. Both Hawk (QA) and Sentinel (Security) must approve independently. No work merges to production without passing both gates.

R

Retrospective

Post-failure analysis documenting what went wrong, root cause, accountability, and prevention measures. Retrospectives are mandatory when tasks fail and are logged to memory for organizational learning.

S

Sentinel

Security reviewer agent responsible for security analysis. Sentinel performs threat modeling, reviews for vulnerabilities, and ensures secure coding practices before work passes the Security Gate.

Sir

Chief Operating Officer (COO) agent — the orchestrator of all Bamwerks operations. Sir coordinates work, dispatches specialists, enforces governance, and reports to the Founder. Sir orchestrates but never implements.

SOUL.md

Agent personality and identity file that defines how an agent thinks, communicates, and operates. Contains core mission, operating principles, personality traits, and boundaries unique to each agent.

Swarm

Functional group of specialized agents organized by domain (e.g., Engineering, Security, Intelligence, Finance). Swarms enable parallel execution, domain expertise, and clear accountability structures.

T

TOTP

Time-based One-Time Password — a 2FA mechanism used for secrets access. Agents must present valid TOTP codes to access sensitive credentials, adding human-in-the-loop approval to automated workflows.
